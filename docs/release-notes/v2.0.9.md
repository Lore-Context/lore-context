# v2.0.9 — Agent Memory Self-Improvement Loop

**Status**: CODE COMPLETE — 6 implementation commits plus 1 E2 release-handoff commit shipped on branch `feat/v2.0.9-agent-memory-self-improvement-loop`. PR-ready locally, pending human review, tag, and production deploy.

**Theme**: Turn agent execution traces into automatic memory quality improvements without asking normal users to label memory quality. A unified recipe contract drives passive eval dataset generation, shadow recipe trials, safe data-recipe proposals, and a promotion gate that keeps production mutation human-gated. Model fine-tuning explicitly deferred — v2.0.9 optimizes memory behavior first.

## Lane Summary

### Lane A — Recipe Contract, Registry, and Architecture Lock (47c71f8)

- `ContextRecipeSpec`, `ContextRecipeTrial`, `PromotionDecision` types + `decidePromotion()` in `@lore/eval`
- `ops/context-recipe.schema.json` — JSON Schema for recipe validation
- `ops/context-recipes/default-v209.json` — the v2.0.9 default baseline recipe
- `mapRecipeToAdapterConfig()` + `mergeRecipeWithBaseConfig()` in `@lore/search` — maps recipe knobs to `SearchAdapterV14Config` without duplicating RRF/fusion logic
- `scripts/ops/check-context-recipes.mjs` + test suite
- Architecture/API docs describe single global architecture line and no-user-labeling principle
- Acceptance: V2.0.9-A1 ✅, V2.0.9-A2 ✅

### Lane B — Automatic Eval Dataset Builder from Agent Evidence (52db4e7)

- Automatic dataset builder converts passive agent evidence into eval cases: used-and-success, used-and-failed, ignored-but-needed, stale-conflict, missing-context, safety-leak
- Outcome signal types for agent task completion, test failure, repeated search, user correction, PR/review failure, stale conflict, safety policy hit
- Sensitive raw content redacted/hashed before storage
- API eval control plane upgraded for recipe-aware v12/v13 dataset runs; `/v1/eval/run` backward compatible
- Acceptance: V2.0.9-B1 ✅, V2.0.9-B2 ✅

### Lane C — Shadow Recipe Trials and Background Runner (8e04162)

- Shadow trial runner comparing baseline vs candidate recipes against the same generated eval set
- Report fields: recall, MRR, stale-hit, negative leak, latency, stream coverage, root-cause hints, budget/cost estimate
- CLI/script entrypoint for local and CI shadow runs
- Disabled-by-default scheduler job wiring (`LORE_CONTEXT_RECIPE_SHADOW_ENABLED=1`)
- No recipe can become active from the scheduler
- Acceptance: V2.0.9-C1 ✅, V2.0.9-C2 ✅

### Lane D — Data Recipe Loop for Memory Quality (f73d4d8 → a64d5e2)

- Data-recipe proposal types for extraction thresholds, inbox auto-accept thresholds, stale/superseded heuristics, merge suggestions, wiki/graph maintenance cadence
- Safe local proposal generation with no user labeling requirement
- High-risk/destructive proposals in admin/operator review only
- Butler/wiki/graph maintenance proposals remain shadow-safe and budget-capped
- Acceptance: V2.0.9-D1 ✅, V2.0.9-D2 ✅

### Lane E — Promotion Gate, Release Controls, and Team Handoff (8359701 + 63abab5)

- Promotion gate checks: draft → candidate → shadow → staged → active → rollback
- Requires baseline-vs-candidate evidence, no safety regressions, bounded latency/cost, rollback metadata
- Active recipe promotion human-gated; scheduler cannot activate recipes
- Linear issues sampled (BRA-625, BRA-629, BRA-634 confirmed); team handoff docs ready
- Acceptance: V2.0.9-E1 ✅, V2.0.9-E2 ✅
