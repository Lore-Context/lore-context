# Lore Cloud v1.9.0 Release Notes

## Summary

v1.9.0 is the **SaaS silent-ship + OSS unlock release**. After v1.7's
production-hardening + Cohere reranker beta and v1.8's partner-activation
foundation + dreaming butler, v1.9 adds:

1. Real Stripe-backed individual subscriptions at four published tiers
   (Free `$0` / Go `$9.99/mo` / Plus `$19.99/mo` / Pro `$99.99/mo`).
2. Auth0 OIDC integration alongside the existing Google OAuth flow.
3. The minimum legal layer for paid SaaS: Privacy Policy v2, Terms of
   Service v2, sub-processors disclosure, cookie consent banner, basic
   carding/spam abuse detection.
4. Public-repository unlock to Apache License 2.0 with v1.3-v1.8
   OSS-eligible code synced into `Lore-Context/lore-context` (which had
   been frozen at the v1.0 boundary).

The release intentionally does not include a public launch event,
multi-region failover, SOC 2 observation kickoff, connector write paths,
reranker self-host GPU GA, or Team/Enterprise tiers. Those are explicit
v2.0 candidates pending v1.9 paying-customer signal.

## Shipped

### Lane F — SaaS Core (individual subscriptions)
- Auth0 adapter (apps/api/src/auth/auth0-adapter.ts) wired into existing
  AuthAdapter contract; coexists with Google OAuth.
- Stripe billing schema (apps/api/src/db/schema-v19-billing.sql) with
  vault-isolated customers, subscriptions, invoices tables.
- Stripe Checkout endpoint (`POST /v1/billing/checkout`) returning hosted
  Checkout session URL for the four tiers.
- Customer portal endpoint (`POST /v1/billing/portal`) for self-serve plan
  upgrades, downgrades, cancellations, and invoice access.
- Stripe webhook handler (`POST /v1/billing/webhook`) with HMAC signature
  verification and dunning state machine
  (3-day grace → 4-day degraded → 7-day suspended).
- Per-tier feature gating module (apps/api/src/billing/feature-gate.ts)
  with documented tier→feature matrix.
- Dashboard pricing page (apps/dashboard/app/billing/page.tsx) with
  current-tier highlight and upgrade flow.
- Public website pricing page (apps/website pricing route).
- Free-tier graceful degradation: 402 Payment Required with
  `upgrade_url` and `required_tier` on gated endpoints.

### Lane S — Minimum legal layer
- Carding detector (apps/api/src/abuse/carding-detector.ts) flags ≥ 5
  failed payment attempts within 60 seconds from the same IP/email.
- Spam onboarding hardening (apps/api/src/abuse/spam-onboarding.ts) with
  per-IP signup rate limit (5/hour) and abuse-score-based CAPTCHA.
- Privacy Policy v2 draft (docs/legal/privacy-policy-v2.md) — refreshed
  for SaaS billing, Stripe data processor disclosure, sub-processor list,
  retention policy, data subject rights. Published only after counsel
  review.
- Terms of Service v2 draft (docs/legal/terms-of-service-v2.md) — paid
  SaaS terms (acceptable use, payment terms, refund policy, liability
  cap, governing law = Singapore). Published only after counsel review.
- Sub-processors page (apps/website/legal/sub-processors) listing
  Cohere, OpenRouter, Anthropic, Stripe, Auth0, Cloudflare, AWS.
- Cookie consent banner (apps/website CookieConsent component) with
  EU/UK detection and 365-day choice persistence.

## How to update from v1.8

For partners running self-hosted Lore: `git pull`, `pnpm install`, run
the schema migration (`pnpm db:apply`), redeploy. The schema migration
adds `customers`, `subscriptions`, `invoices`, and abuse-signals tables;
existing v1.8 vaults continue working without needing a Stripe
subscription.

For hosted partners: cutover happens automatically during the v1.9.0
production deploy. Existing partners are auto-mapped to a temporary
"Pro complimentary" subscription for the first 30 days; ops will
communicate transition timing per partner.
