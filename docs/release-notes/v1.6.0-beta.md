# Lore Cloud v1.6.0-beta Release Notes (draft)

## Summary

v1.6.0-beta is the **Production Hardening + Secrets Beta** for the private
cloud line. It closes Lane A audit caller wiring (search audit table now
receives 1%-sampled rows in production), migrates all production credentials
from plaintext on-disk to AWS Secrets Manager with a hard-fail bootstrap
gate, brings GitHub Actions release automation onto OIDC short-lived
credentials, and relocks the 12 v14 CloudWatch alarm thresholds against a
formal v1.6 baseline.

It is honest about what was deferred. **Lane B (reranker GA on Spot G4dn) was
rejected by AWS quota review on 2026-05-04 and is deferred to v1.7.** The
On-Demand G/VT increase request remains open with AWS support. **Lane F
(SaaS GA path) is deferred to v1.7** as scope work, not a regression. **The
v1.6 SLO baseline is synthetic-only** because production has zero real
partner search traffic; real-traffic recalibration of the 12 alarm
thresholds is a v1.7 deliverable.

The v1.6 line ships against the same v1.4 image lineage (`embedding-cache`,
`search-adapter-v14`, `orchestrator-v12`, `wiki-compiler-v13`, +
`memory-search-audit` caller-wired). Production runs against
`ghcr.io/lore-context/lore-context-api:8ca3ab215e3d`, which is the merge
HEAD of the secrets-migration line through PR #100.

## What changed since v1.5.0-beta

### Lane 0 — GitHub Actions OIDC auth (PR #79)

The release-artifacts and deploy workflows previously authenticated to AWS
with a long-lived access key stored in `secrets.AWS_ACCESS_KEY_ID` /
`AWS_SECRET_ACCESS_KEY`. Lane 0 swaps that for OIDC short-lived credentials
via `aws-actions/configure-aws-credentials@v4` against the
`arn:aws:iam::…:role/lore-github-actions-deploy` role. The IAM trust policy
restricts assumption to `repo:lore-context/lore-cloud` GitHub OIDC subjects.

The long-lived AWS access key is rotated out of GitHub Actions secrets as
part of the v1.6 closure. Workflows now expire credentials after one hour;
no static credentials remain in the repo or in GitHub-managed secrets.

### Lane A — search audit caller wiring (PR #77)

`SearchAuditRecorder` was added in v1.5 (Lane C-2 schema) but its caller
invocation in `apps/api/src/index.ts:/v1/memory/search` handler was never
landed. Lane A wires the 1%-sampled audit recorder into the search path:
each request that passes the sample gate writes a row to the
`memory_search_audit` table with vault id, query hash, top-K result ids and
their scores, and stream attribution. PII is hashed before write; no
plaintext query text is persisted.

A regression test in `apps/api/src/__tests__/audit-recorder.test.ts`
asserts that the recorder fires for the sampled fraction and is a strict
no-op for the unsampled fraction. CI green on PR #77.

### Lane D — release/deploy + onboarding infrastructure (PRs #79, #84, #86, #98)

Several smaller infra PRs landed across the v1.6 window:

- PR #79: staging + production deploy automation runbook
  (`docs/v1.6-lane-0-deploy-automation-runbook.md`); GitHub Actions OIDC
  short-lived credentials replace the long-lived AWS access key.
- PR #84: partner onboarding playbook + questionnaire + data handling
  templates (`docs/onboarding/`).
- PR #86: real-traffic baseline collection + threshold verifier
  (`scripts/release/collect-real-traffic-baseline.mjs`,
  `scripts/release/verify-baseline-vs-thresholds.mjs`) — used by Lane E.
- PR #98: onboarding funnel progress table migration
  (`schema-v16-onboarding-funnel.sql`). Applied imperatively to staging +
  production RDS via SSM RunCommand on 2026-05-08. Adding it to the
  `prod.mjs` schema list so future deploys re-apply idempotently is a v1.7
  cleanup follow-up.

### Lane B — reranker GA → DEFERRED to v1.7

Lane B's plan was to deploy the v1.5-fixtures reranker container
(`@xenova/transformers` ms-marco-MiniLM-L-6-v2 ONNX) onto a `g4dn.xlarge`
Spot instance with the existing v14 ECS cluster, re-baseline GPU
utilization, and lock `lore-reranker-restart-rate` to the OOM target.

AWS rejected the Spot G4dn quota increase on 2026-05-04 with the boilerplate
"insufficient capacity in target region" reason. The On-Demand G/VT
instance increase request was opened the same day and remains pending AWS
quota review (25h+ as of v1.6 closure).

v1.6 ships without reranker in production. SLO 5 (reranker GPU OOM) tracking
start date is deferred to v1.7. The provisional charter constant 1 alarm
threshold is preserved on `lore-reranker-restart-rate` but evaluates
against zero datapoints.

Cohere reranker A/B comparison (originally Lane B Phase 2) is also deferred.

### Lane C — secrets migration (PRs #78, #85, #90–#94, #97, #100)

Seven plaintext credentials lived on `/opt/lore/.env.production` (or its
sidecar variant) since v1.4. v1.5 deferred the migration as too risky for
the window. v1.6 closes the migration end-to-end:

**Bootstrap**. `scripts/secrets/bootstrap-secrets.mjs` (PR #78) reads a
13-key `SECRET_MAP` (7 required, 6 optional) from a source `.env` file
and provisions the corresponding `lore-{prod|staging}/<suffix>` AWS
Secrets Manager namespace via `CreateSecretCommand`. Idempotent on
re-run (`ResourceExistsException` is a soft skip). Ships with a 14-test
Vitest suite in `scripts/secrets/tests/bootstrap-secrets.test.mjs`. PR
#92 expanded the map from the original 7-secret design to the 13-key
list after staging audit. PR #91 extended the IAM staging policy and
shipped the 4 cutover runbooks.

**Resolver**. `apps/api/src/secrets/aws-resolver.ts` (Lane C resolver,
PR #90 — `feat(v1.6-lane-c): container entrypoint with Secrets Manager
bootstrap (v2)`) accepts `secretsmanager://lore-{prod|staging}/<suffix>`
URI references and resolves them to plaintext at API container startup
via `@aws-sdk/client-secrets-manager`. Resolution failures emit metric
`secretsBootstrapMode: hard-fail|fallback|skipped` to `/health` for
operator visibility. The resolver is gated behind `AWS_SECRETS_ENABLED=1`
and is a strict no-op when the flag is unset.

**Validation**. `scripts/secrets/validate-env-references.mjs` lints any
`.env` file for plaintext-vs-reference correctness across the 13 secret
keys. Used in CI on every push that touches `.env*` patterns and in the
deploy preflight (`scripts/release/prod.mjs`).

**Production cutover**. 2026-05-08T14:01Z. Production
`/opt/lore/releases/v1.4.0-beta-cache-20260505T233542Z/.env.production-sidecar`
replaced 9 plaintext secrets with `secretsmanager://[redacted]<suffix>`
references. `LORE_SECRETS_BOOTSTRAP_FAIL_MODE=hard-fail` set per plan
§15.4 (production: never fall back to plaintext on resolver failure;
staging: `fallback` for safer experimentation).

**Verification**. Production `/health` responds with
`secretsBootstrapMode: "hard-fail"`,
`secretsBootstrapTimestamp: "2026-05-08T14:01:14.766Z"` proving the
resolver path executed. External Cloudflare tunnel `api.lorecontext.com`
returned 200 OK on 5 sequential probes. Container restart count: 0
post-cutover.

**Deferral**. `LORE_JWT_SECRET` was demoted from required to optional
(PR #100) after audit revealed production never had it set; the v1.4
auth path uses `SESSION_SECRET` end-to-end. Required count: 7. Optional:
6. Total `SECRET_MAP` entries: 13.

### Lane C.5 — staging cutover (PRs #93, #94, #97, #99)

Staging cutover landed 2026-05-08 ahead of production. Surfaced 13 reality
gaps (compose env_file vs environment block pass-through, Dockerfile
ENTRYPOINT vs compose `command:` interaction, `process.argv[1]` startup
guard mismatch when entrypoint is a wrapper, preflight psql parsing of
`secretsmanager://` URLs, etc.). All 13 gaps fixed via in-place patches
during cutover; the persistence path was PR #93 (runbook truth-up), PR
#94 (LORE_AUDIT_HASH_SALT YAML quote fix), PR #97 (compose env pass +
preflight `secretsmanager://` guard), and PR #99 (Week 3 staging
cutover handoff doc).

PR #97 in particular added `AWS_SECRETS_ENABLED`,
`LORE_SECRETS_BOOTSTRAP_FAIL_MODE`, `LORE_SECRETS_BOOTSTRAP_TIMESTAMP`
to the api / memory-worker / dashboard service `environment:` blocks in
`docs/deployment/compose.production.yml`, which is the byte-canonical
form. The production runtime stack
(`/opt/lore/releases/.../docker-compose.v14-cache-sidecar.yml`) was
patched in-place during cutover; reconciling the production drift back to
repo is tracked as a v1.7 follow-up.

now supported without behaviour change.

## Migration notes

No customer data migration is required. Operator sequence is a one-time
cutover already executed during release window:

1. Run `scripts/secrets/bootstrap-secrets.mjs --target prod --source-env
   /opt/lore/.../.env.production-sidecar` to provision `[redacted]*`
   secrets from current plaintext .env. Idempotent.
2. Replace plaintext values in the active `.env.production-sidecar` with
   `secretsmanager://[redacted]<suffix>` references for all 9 keys.
3. Set `AWS_SECRETS_ENABLED=1`,
   `LORE_SECRETS_BOOTSTRAP_FAIL_MODE=hard-fail`,
   `LORE_API_IMAGE=ghcr.io/lore-context/lore-context-api:8ca3ab215e3d` in
   the same env file.
4. `docker compose -f /opt/lore/releases/v1.4.0-beta-cache-20260505T233542Z/docker-compose.v14-cache-sidecar.yml down api && docker compose -f /opt/lore/releases/v1.4.0-beta-cache-20260505T233542Z/docker-compose.v14-cache-sidecar.yml up -d api`
   — production runs the sidecar compose stack, NOT
   `docs/deployment/compose.production.yml`. Always pass `-f <path>`
   explicitly. (Repo drift; reconciliation is a v1.7 cleanup.)
5. Verify `/health` returns `secretsBootstrapMode: "hard-fail"` with a
   recent `secretsBootstrapTimestamp`.
6. Verify external tunnel `api.lorecontext.com/health` returns 200.
7. Backup the prior plaintext env to
   `.env.production-sidecar.bak-pre-secrets-2026-05-08` (14-day retention).
8. `shred` any local copies of plaintext secrets used during cutover.

## Known limitations

- **Real-traffic SLO truth-up not done.** The 12 v14 alarms are locked to
  charter floors, not evidence-driven thresholds, because production has
  zero partner traffic. Re-baseline + re-relock is a v1.7 deliverable
  contingent on partner notification distribution.
- **Reranker not in production.** Lane B Spot G4dn quota was rejected by
  AWS on 2026-05-04. SLO 5 (reranker GPU OOM) tracking start defers to
  v1.7.
- **Capture-to-recall probe not run.** SLO 4 baseline remains TODO from
  v1.4 charter. v1.7 deliverable.
- **Production runtime compose file is repo-drift.**
  `/opt/lore/releases/.../docker-compose.v14-cache-sidecar.yml` does not
  have a source-of-truth in the repo; the canonical
  `docs/deployment/compose.production.yml` is byte-aligned but not the
  one production runs. Reconciling the drift is a v1.7 cleanup item.
- **`schema-v16-onboarding-funnel.sql` not in prod.mjs schema list.**
  Applied imperatively during release. Future deploys won't auto-apply
  until added to the script. v1.7 cleanup.
- **`release-artifacts.yml` auto-trigger broken since 2026-05-08T15:22Z.**
  Push events to main no longer fire the workflow. Manual
  `gh workflow run release-artifacts.yml --ref main -f ref=$SHA` per
  merge as workaround. v1.7 investigation.
- **Lane C.6 rotation drill not executed.** Scheduled T+7 = 2026-05-15.
