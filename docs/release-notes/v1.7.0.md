# Lore Cloud v1.7.0 Release Notes

## Summary

v1.7.0 closes the partner-ramp hardening release. It merges the critical
multi-tenant isolation fixes, high-priority production stability work, medium
defense-in-depth items, cleanup debt from v1.6, and the Cohere-backed reranker
implementation with stub fallback.

The release intentionally does not claim real partner SLO recalibration. The
v1.7 plan required at least three design partners with seven days of production
traffic before locking real-traffic thresholds. That gate is not met at v1.7
cutover time, so real-traffic SLO truth-up and capture-to-recall probe work are
carried forward to v1.8.

## Shipped

- S1-S5: critical multi-tenant isolation and production crash blockers.
- S6-S14: request timeout, Redis timeout, rate limiter, DB pool, cold-start,
  embedding circuit breaker, audit, host allowlist, and legacy key shadow fixes.
- S15-S19: cloud-store vault filters, security headers, error redaction,
  secure-cookie default, and production SSL mode rejection.
- A1.1/A1.2: Cohere reranker client, factory, fallback behavior, and v12
  orchestrator wiring.
- A2/A4/A5/A6: version bump, schema list, Jina secret mapping, and
  release-artifacts trigger audit.
- A3: production v14 sidecar compose drift reconciled into
  `docs/deployment/compose.v14-cache-sidecar.yml`.

## Gated Or Deferred

- A1.3: production Cohere cutover is executed during the v1.7.0 deployment.
  Rollback is `LORE_RERANKER_PROVIDER=stub` plus API restart.
- A7: real-traffic SLO baseline is deferred to v1.8 because the CloudWatch
  `Lore/API RequestCount` seven-day window has no datapoints at cutover time.
- A8: capture-to-recall probe is deferred with A7 because it depends on the
  real-traffic baseline.
- A9: automated rotation Lambda remains optional and is carried forward to v1.8
  after the production cutover is stable.
